# Implementation Plan - Internationalisation (i18n)

## 1. 🔍 Analysis & Context
*   **Objective:** Implement internationalization (FR/EN) for the frontend with centralized translation files, including dynamic language switching from the user menu and synchronization with Day.js/MUI date formats.
*   **Affected Files:**
    *   `app/frontend/package.json`
    *   `app/frontend/src/i18n/config.ts` (new)
    *   `app/frontend/src/i18n/locales/fr.json` (new)
    *   `app/frontend/src/i18n/locales/en.json` (new)
    *   `app/frontend/src/main.tsx`
    *   `app/frontend/src/App.tsx`
    *   `app/frontend/src/components/layout/Sidebar.tsx`
    *   `app/frontend/src/pages/LoginPage.tsx`
    *   `GEMINI.md`
    *   `Architecture.md`
*   **Key Dependencies:** `i18next`, `react-i18next`, `i18next-browser-languagedetector`, `dayjs`.
*   **Risques/Inconnues:** Ensuring seamless synchronization between the selected language and the `dayjs` locale used by MUI DatePickers to avoid date format inconsistencies without page reload.

## 3. 📝 Step-by-Step Implementation Details

### Step 1: Install i18n Dependencies
*   **Goal:** Add necessary libraries to the project.
*   **Action:**
    *   Run command in `app/frontend`: `npm install i18next react-i18next i18next-browser-languagedetector`
*   **Verification:** Check `package.json` for new dependencies.

### Step 2: Configure i18n Engine & Resource Files
*   **Goal:** Set up the i18next instance and create centralized translation JSONs.
*   **Action:**
    *   Create directory `app/frontend/src/i18n/locales`.
    *   Create `app/frontend/src/i18n/locales/fr.json`:
        ```json
        {
          "common": {
            "loading": "Chargement...",
            "language": "Langue",
            "logout": "Déconnexion"
          },
          "sidebar": {
            "home": "Accueil",
            "pastSprints": "Sprints Passés",
            "admin": "Admin",
            "teams": "Équipes",
            "users": "Utilisateurs",
            "sprints": "Sprints",
            "login": "Connexion",
            "reportBug": "Signaler un bug",
            "mode": "Mode {{mode}}"
          },
          "login": {
             "signInGithub": "Se connecter avec GitHub"
          }
        }
        ```
    *   Create `app/frontend/src/i18n/locales/en.json` (Mirror structure with English values).
    *   Create `app/frontend/src/i18n/config.ts`:
        *   Import `i18next`, `initReactI18next`, `LanguageDetector`.
        *   Import JSON files.
        *   Call `i18n.use(LanguageDetector).use(initReactI18next).init({...})` with `resources`, `fallbackLng: 'en'`, `interpolation: { escapeValue: false }`.

### Step 3: Implement Dynamic Locale Management
*   **Goal:** Ensure Day.js and MUI localized components react to language changes.
*   **Action:**
    *   Modify `app/frontend/src/main.tsx`:
        *   Remove `dayjs.locale(...)` and `LocalizationProvider` setup.
        *   Import `./i18n/config`.
    *   Modify `app/frontend/src/App.tsx`:
        *   Import `useTranslation` from `react-i18next`.
        *   Import `dayjs` and locales (`import 'dayjs/locale/fr'; import 'dayjs/locale/en';`).
        *   Import `LocalizationProvider` and `AdapterDayjs`.
        *   Inside `App` component:
            *   `const { i18n } = useTranslation();`
            *   `useEffect(() => { dayjs.locale(i18n.language); }, [i18n.language]);`
            *   Wrap the `Routes` or existing context providers with `<LocalizationProvider dateAdapter={AdapterDayjs} adapterLocale={i18n.language}>`.

### Step 4: Add Language Selector to Sidebar User Menu
*   **Goal:** Allow users to switch language from the UI.
*   **Action:**
    *   Modify `app/frontend/src/components/layout/Sidebar.tsx`:
        *   Import `useTranslation`.
        *   Destructure `{ i18n }` from `useTranslation()`.
        *   Create `changeLanguage` function (e.g., `i18n.changeLanguage(i18n.language === 'fr' ? 'en' : 'fr')`).
        *   Add a `MenuItem` in the User Menu (below "Dark/Light Mode"):
            *   Icon: `LanguageIcon` (from `@mui/icons-material/Language`).
            *   Text: Display current or target language (e.g., "Français" if current is EN).
            *   OnClick: Call `changeLanguage`.

### Step 5: Migrate Existing Text to Keys
*   **Goal:** Replace hardcoded strings with translation keys.
*   **Action:**
    *   **Sidebar (`src/components/layout/Sidebar.tsx`)**:
        *   Replace "Home" -> `t('sidebar.home')`
        *   "Past Sprints" -> `t('sidebar.pastSprints')`
        *   "Admin" -> `t('sidebar.admin')`
        *   "Teams", "Users", "Sprints" -> `t('sidebar.teams')`, etc.
        *   "Report a Bug" -> `t('sidebar.reportBug')`
        *   "Logout" -> `t('common.logout')`
    *   **Login Page (`src/pages/LoginPage.tsx`)**:
        *   Replace title/button text with `t('login.signInGithub')`.

### Step 6: Documentation Update
*   **Goal:** Update project documentation.
*   **Action:**
    *   Update `GEMINI.md`: Add guidelines for adding new translations.
    *   Update `Architecture.md`: Mention i18n stack in Frontend section.

## 4. 🧪 Testing Strategy
*   **Unit Tests:** Verify `i18n` initializes correctly.
*   **Manual Verification:**
    1.  Start app (`npm run dev`).
    2.  Check default language detection (should match browser).
    3.  Open Sidebar User Menu -> Switch Language.
    4.  Verify Sidebar text changes immediately.
    5.  Verify DatePicker (if accessible in admin/sprints) formats update (e.g., Month order).
    6.  Reload page -> Language selection should persist (handled by `i18next-browser-languagedetector` in localStorage).

## 5. ✅ Success Criteria
*   Application builds successfully.
*   User can switch between English and French.
*   Selection persists across reloads.
*   Dates are formatted according to the selected locale.
